# EXP-001 Audit — 2026-09-15

## Purpose

Final audit of EXP-001 after the controlled Android runtime and controlled render-target checkpoints were completed.

## Current decision

EXP-001 is **CLOSED AT THE MINECRAFT TARGET BOUNDARY**.

The controlled Android portion is CONFIRMED. The retail Minecraft loading portion is BLOCKED / NOT TESTED because no authorized, reproducible, reversible, observable loading path into the Minecraft process has been established.

This is a deliberate boundary, not a claim that integration is impossible.

These facts establish target inventory only. They do not establish a renderer hook point or bridge execution inside Minecraft.

## Boundary rationale

Android's application model separates applications into sandboxed processes/UIDs. Native libraries are normally made available to the package that declares/loads them; `<uses-native-library>` controls native-library accessibility for an application and is not a mechanism for attaching an unrelated library to another application's process.

Official references:
- https://developer.android.com/guide/topics/manifest/uses-native-library-element
- https://source.android.com/docs/compatibility/17/android-17-cdd

Accordingly, the project will not treat cross-process loading, security-boundary bypass, stealth persistence, or unauthorized process modification as an experimental shortcut.

## EXP-002 disposition

EXP-002 is released from HOLD only in a revised, observation-first form. It must not assume that the PVR bridge executes inside retail Minecraft.

Revised scope:

1. inventory the Minecraft target and its observable native/runtime metadata;
2. map publicly documented renderer/native boundaries;
3. compare those observations against the controlled render-target contract;
4. identify a legitimate integration path only if it can be demonstrated in a controlled/researcher-owned environment;
5. stop before any unauthorized process modification or security-boundary bypass.
