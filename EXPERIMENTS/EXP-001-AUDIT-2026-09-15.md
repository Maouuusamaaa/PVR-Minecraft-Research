# EXP-001 / EXP-002 Consistency Audit — 2026-09-15

## Scope

Audit the experiment state, controlled render target, bridge implementation, and EXP-002 gate after the 2026-09-15 Android runtime work.

## Findings

### 1. EXP-001 status is now internally defined

The controlled Android checkpoint is **COMPLETE / CONFIRMED**. The Minecraft target boundary remains **BLOCKED / NOT TESTED**.

This distinction is intentional. A successful controlled application test is not evidence of execution inside the Minecraft retail process.

### 2. Controlled Render Target wording was reconciled

The testbed was previously described as the environment "after EXP-001" even though its runtime checkpoint is being used as part of the EXP-001 evidence chain. The documentation now describes it as the controlled renderer environment established during EXP-001 and a calibration environment for EXP-002.

### 3. Graphics-backend wording was reconciled

The testbed implementation uses OpenGL ES 2/EGL. The documentation previously described Vulkan as the preferred first backend while the actual implementation was GLES. The documentation now records the implemented backend as OpenGL ES and treats Vulkan as a future separate controlled-backend candidate.

This is important because Android notes that library/log evidence alone can be insufficient to determine the active graphics API. The testbed therefore records the API directly from its graphics context.

### 4. Bridge scope was narrowed in implementation documentation

The bridge CMake documentation previously described its objective as being loadable into the Minecraft Bedrock process. It now explicitly describes a researcher-controlled Android application boundary and does not imply that Minecraft loading has been demonstrated.

### 5. Renderer-to-bridge evidence was strengthened

`bridge_initialize()` now records PID/TID. This allows the renderer-thread identity to be correlated directly with the explicit bridge call rather than relying only on process-level log grouping.

### 6. EXP-002 remains correctly gated

EXP-002 is still HOLD. Its current design asks for target-side observation and does not require unsupported assumptions about RenderDragon, BGFX, or a particular production function.

## Decision

Do not advance to EXP-002 under the current objective.

The immediate next technical action is CI rebuild/verification of the bridge and controlled renderer after the documentation/instrumentation changes. After that, the project can either:

1. continue authorized target-boundary research in a researcher-controlled test installation; or
2. formally close the Minecraft portion of EXP-001 as BLOCKED and define a revised controlled EXP-002 that does not assume execution inside retail Minecraft.
