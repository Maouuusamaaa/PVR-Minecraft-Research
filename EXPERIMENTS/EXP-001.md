# EXP-001 — Native Library Loading

## Objective

Determine whether a controlled native bridge/library can be loaded into a Minecraft Bedrock Android process without assuming a specific RenderDragon symbol or renderer hook.

## Status

**CONTROLLED ANDROID RUNTIME CHECKPOINT CONFIRMED; MINECRAFT TARGET BLOCKED / NOT TESTED.**

The bridge has been built for Android ARM64, packaged in a signed Android harness, installed on the user's Android 13 device, loaded by the Android runtime in the controlled harness process, and observed emitting `PVR_BRIDGE_LOADED`.

The target Minecraft installation has now also been characterized directly on the device: package `com.mojang.minecraftpe`, version `1.26.45.1`, versionCode `972604501`, ARM64 process, PID `11196`, and an extracted native-library directory containing `libminecraftpe.so` and supporting native libraries.

This target-side inspection does **not** prove that the bridge can be loaded into Minecraft. Direct `/proc/11196/maps` and `/proc/11196/exe` access is denied to the available shell context, and no authorized, reproducible, reversible target-side loading method has been established.

Therefore EXP-001 is not complete for the Minecraft target. The controlled Android loading checkpoint remains confirmed, while the Minecraft target boundary is explicitly `BLOCKED / NOT TESTED`.

### Controlled Android runtime

The signed harness APK was installed with Android's package manager and returned `Success`. The package manager subsequently listed `com.pvr.exp001.harness`.

The harness was launched as package `com.pvr.exp001.harness`. Logcat recorded the bridge constructor, PID/TID, the required marker, initialization completion, and the explicit initialization call:

PVR-Bridge: Bridge initialization complete

Therefore:

PVR_BRIDGE_LOADED = CONFIRMED

The native-library directory was identified through Package Manager and contained `libminecraftpe.so` at approximately 299 MB, together with the other ARM64 native libraries documented in `EXP-001-RUNTIME-TEST.md`.

`libminecraftpe.so` was identified as an ELF64 AArch64 shared object for Android 26, built by NDK r28c, stripped, with Build ID `868e275cb295e9a275bb29d2258edc2f7dc48761`.

### Target process access boundary

The following read-only checks returned permission errors:

```text
/proc/11196/maps -> Permission denied
/proc/11196/exe  -> Permission denied
```

`dumpsys meminfo 11196` confirmed native/shared-object memory activity but did not expose individual library names. It is therefore not accepted as bridge-loading evidence.

## What This Experiment Does NOT Prove

- It does not prove compatibility with Minecraft's renderer.
- It does not prove that the bridge can be loaded into Minecraft.
- It does not prove that RenderDragon code can be reached.
- It does not prove that a render-thread callback can be obtained.
- It does not prove that PVR can execute inside Minecraft.
- It does not prove GPU work or renderer modification.

## Target Minecraft Test

The target-side success criterion remains a reproducible native initialization event from the controlled bridge **inside the target Minecraft process**, with the exact Minecraft version, Android version, ABI, package/process identity, PID/TID, loading method, library path, timestamp and unedited logcat evidence recorded.

The target installation has been identified, but the repository still does not contain a legitimate, reproducible and reversible loading mechanism for placing the bridge into the installed retail Minecraft process. The native-library directory is evidence of packaged native code, not a loading mechanism.

## Decision / Boundary

Do **not** proceed to EXP-002 solely because the controlled harness succeeded or because Minecraft's native libraries are visible.

The correct current decision is:

```text
Controlled Android native loading = CONFIRMED
Minecraft target loading          = BLOCKED / NOT TESTED
EXP-001 overall                   = NOT CONFIRMED
EXP-002                           = HOLD
```

The next research action is to establish an authorized, reproducible, reversible integration path for a target installation that the researcher controls. If such a path cannot be established without bypassing Android/Minecraft protections or modifying/distributing proprietary production binaries, the Minecraft portion remains `BLOCKED` and the controlled-harness result is preserved as a valid lower-level checkpoint.

## Research Boundary

No proprietary Minecraft APKs, Mojang native libraries, extracted proprietary binaries, copyrighted assets, private device identifiers, or unrelated personal logs are committed to the research repository. Only source, documentation, experiment notes, scripts and configuration belong here.
