# EXP-001 — Native Library Loading

## Objective

Determine whether a controlled native bridge/library can be loaded and initialized in an Android application, while keeping the Minecraft target boundary explicit and evidence-based.

## Status

**CONTROLLED ANDROID RUNTIME = CONFIRMED; MINECRAFT TARGET = BLOCKED / NOT TESTED.**

The bridge has been built for Android ARM64, packaged in a signed Android harness, installed on the user's Android 13 device, loaded by the Android runtime, and observed executing a sustained native rendering loop in the controlled render target.

The target Minecraft installation has also been characterized directly on the device: package `com.mojang.minecraftpe`, version `1.26.45.1`, versionCode `972604501`, ARM64 process, PID `11196`, with `libminecraftpe.so` and supporting native libraries present in its application library directory.

This target-side inspection does **not** prove that the bridge can be loaded into Minecraft. Direct `/proc/11196/maps` and `/proc/11196/exe` access is denied to the available shell context, and no authorized, reproducible, reversible target-side loading method has been established.

### Controlled Android runtime

The corrected Controlled Render Target APK was installed and launched on the Android device. The runtime evidence recorded PID `24351` and render-thread TID `24382`.

Logcat showed a sustained native render loop with the expected sequence:

```text
PVR-RenderTarget: FRAME_BEGIN frame=2658 pid=24351 tid=24382
PVR-RenderTarget: FRAME_RENDERED frame=2658
PVR-RenderTarget: FRAME_PRESENT frame=2658
...
PVR-RenderTarget: FRAME_BEGIN frame=2726 pid=24351 tid=24382
PVR-RenderTarget: FRAME_RENDERED frame=2726
PVR-RenderTarget: FRAME_PRESENT frame=2726
PVR-RenderTarget: RENDER_THREAD_STOP
```

Frames 2658 through 2726 were observed with the expected BEGIN → RENDERED → PRESENT sequence. The render thread subsequently stopped normally.

Therefore:

```text
Android native library loading in controlled environment = CONFIRMED
Native render thread execution                       = CONFIRMED
Repeated frame rendering                            = CONFIRMED
Frame presentation                                  = CONFIRMED
Controlled render-target runtime                    = CONFIRMED
```

Detailed evidence is recorded in `EXPERIMENTS/EXP-001-RUNTIME-2026-09-15.md`.

The native-library directory contained `libminecraftpe.so` at approximately 299 MB, together with the other ARM64 native libraries documented in `EXP-001-RUNTIME-TEST.md`.

`libminecraftpe.so` was identified as an ELF64 AArch64 shared object for Android 26, built by NDK r28c, stripped, with Build ID `868e275cb295e9a275bb29d2258edc2f7dc48761`.

### Target process access boundary

The following read-only checks returned permission errors:

```text
/proc/11196/maps -> Permission denied
/proc/11196/exe  -> Permission denied
```

`dumpsys meminfo 11196` confirmed aggregate native/shared-object memory activity but did not expose individual library names. It is therefore not accepted as bridge-loading evidence.

## What This Experiment Does NOT Prove

- It does not prove compatibility with Minecraft's renderer.
- It does not prove that the bridge can be loaded into Minecraft.
- It does not prove that RenderDragon code can be reached.
- It does not prove that a render-thread callback can be obtained.
- It does not prove that PVR can execute inside Minecraft.
- It does not prove GPU work or renderer modification inside Minecraft.

## Target Minecraft Test

The target-side success criterion remains a reproducible native initialization event from the controlled bridge **inside the target Minecraft process**, with the exact Minecraft version, Android version, ABI, package/process identity, PID/TID, loading method, library path, timestamp and unedited logcat evidence recorded.

The target installation has been identified, but the repository still does not contain a legitimate, reproducible and reversible loading mechanism for placing the bridge into the installed retail Minecraft process. The native-library directory is evidence of packaged native code, not a loading mechanism.

## Decision / Boundary

The controlled runtime checkpoint is now complete and confirmed. **Do not treat it as Minecraft renderer integration.**

```text
Controlled Android native loading = CONFIRMED
Controlled native rendering       = CONFIRMED
Minecraft target loading          = BLOCKED / NOT TESTED
EXP-001 controlled checkpoint     = COMPLETE
EXP-002                           = HOLD
```

The next research action is to establish an authorized, reproducible, reversible integration path for a target installation that the researcher controls. If such a path cannot be established without bypassing Android/Minecraft protections or modifying/distributing proprietary production binaries, the Minecraft portion remains `BLOCKED` and the controlled-harness result is preserved as a valid lower-level checkpoint.

## Research Boundary

No proprietary Minecraft APKs, Mojang native libraries, extracted proprietary binaries, copyrighted assets, private device identifiers, or unrelated personal logs are committed to the research repository. Only source, documentation, experiment notes, scripts and configuration belong here.
