## Public architecture evidence

### 1. Android native-library and process boundary

Android documents that native shared-library accessibility is package/application scoped. The `<uses-native-library>` mechanism makes a vendor-provided native library accessible to an application; it is not documented as a generic cross-process attachment mechanism. Android's process model also states that an application's components normally execute in that application's process, while shared processes across applications require shared Linux UID and signing conditions.

References:
- https://developer.android.com/guide/topics/manifest/uses-native-library-element
- https://developer.android.com/guide/components/processes-and-threads

Android 12+ documentation further states that native shared-library dependencies are enforced for applications targeting API 31+, reinforcing that native-library availability is part of the package/runtime contract rather than a generic external attachment facility.

Reference: https://developer.android.com/about/versions/12/reference/compat-framework-changes

Classification: **CONFIRMED** for the platform model.

### 2. Public Android Minecraft native-forwarder architecture

KafkaLauncher is a public proof-of-concept for Minecraft Bedrock Android 1.21.51.02. Its repository describes an alternative launcher/process architecture for that specific version.

Reference: https://github.com/EnderNebula/KafkaLauncher

This demonstrates that a researcher-controlled alternative package/process architecture has existed publicly for a specific Minecraft version. It does **not** prove that the same architecture applies to Minecraft 1.26.45.1, and it does not identify a RenderDragon hook point for the current target.

Classification: **CONFIRMED as public historical architecture evidence; NOT CONFIRMED for the current target**.

### 3. Public RenderDragon shader/material evidence

Public RenderDragon shader projects continue to document Android support for Minecraft 1.26+ and use RenderDragon material/shader artifacts. For example, the `newb-x-mcbe` project currently states support for Minecraft Bedrock 1.26+ across Windows/Android/iOS and documents Android loader-based workflows.

Reference: https://github.com/devendrn/newb-x-mcbe

The Android RenderDragon shader-list documentation also records Android workflows involving modified packages and material files under `assets/renderer/materials`.

Reference: https://github.com/DominoKorean/Render-dragon-shader-list/blob/main/docs/installation/android.md

These sources are useful evidence that the Android RenderDragon material layer is actively studied and customized in the community. They do not expose the production native frame-submission call chain and therefore cannot identify a safe PVR integration point by themselves.

Classification: **CONFIRMED for shader/material ecosystem evidence; UNKNOWN for native submission path**.

### 4. Current Minecraft 1.26 renderer evidence

Microsoft's Minecraft Bedrock 1.26.0 update documentation explicitly contains a `RenderDragon for Creators Experiment` section and records Android/PlayStation support for colored block lights in the Vibrant Visuals preview. This confirms that RenderDragon is an active renderer-facing feature area in the 1.26 generation.

Reference: https://learn.microsoft.com/en-us/minecraft/creator/documents/update1.26.0?view=minecraft-bedrock-stable

This is product-level renderer evidence, not native call-chain evidence. It does not reveal the exact Android `libminecraftpe.so` function, thread, BGFX encoder, submission point, or backend function used by Minecraft 1.26.45.1.

Classification: **CONFIRMED for product-level RenderDragon evidence; UNKNOWN for native runtime boundary**.

## Evidence interpretation

The combined evidence supports the following bounded conclusion:

1. Minecraft Android has a substantial native runtime centered on `libminecraftpe.so`.
2. Android's normal application model treats native-library availability and process execution as package/process concerns; it does not document a generic package-independent native-library attachment mechanism.
3. Public Minecraft Android projects have used controlled package/process architectures to study or extend native behavior for specific versions.
4. Public RenderDragon material/shader projects provide renderer-facing evidence and current 1.26-era compatibility context, but they do not establish the production native frame/submission path.
5. Therefore the exact RenderDragon frame/render boundary for Minecraft `1.26.45.1` remains **UNKNOWN**.
